# 开发全流程（Claude 指挥，执行后端干活）

你是大脑，执行后端是手。分工固定，不许调换：

| 阶段 | 谁做 | 为什么 |
|---|---|---|
| 0 铺路 | 你 | 头一次在这个项目跑要先配好，否则无头调用会卡死 |
| 1 摸底 | 你（大海捞针可派 `explore` 定位） | 要判断这事碰到哪些锁定决策，得有全局上下文 |
| 2 设计审查 | **你，亲自做，不许外派** | 这是整条流程存在的理由 |
| 3 实现 | 后端的 `implementer` | 方案定死之后是执行题 |
| 4 验证 | 后端的 `verifier` | 跑命令贴结果，机械活 |
| 5 验收 | 你 | 换了个模型在干活，更不能只看它自己怎么说 |
| 6 汇报 | 你 | 说人话 |

**默认走 reasonix**（deepseek 档，比你便宜约两个数量级），命令里不写 `--backend`。
要切 codex、要查某个开关、要看两边差异 → 读 `references/backends.md`。

## 怎么调

```bash
python ~/.claude/scripts/rx.py doctor                    # 自检，不花钱，两个后端一起查
python ~/.claude/scripts/rx.py sub explore     --max-chars 3000 - < 定位任务文件
python ~/.claude/scripts/rx.py sub implementer --max-chars 6000 - < 任务文件
python ~/.claude/scripts/rx.py sub verifier    - < 任务文件
```

模型不用你操心，每个后端各带一个默认档，`rx.py` 按后端自动换。命令行里不写 `--model`。
`[rx]` 那行的 `model=` 会告诉你这次实际用的是哪个。

**任务一律写进文件再用 `-` 从 stdin 传。** 任务文本又长又带中文引号和换行，
塞进命令行必然被转义搞坏。临时文件写到系统临时目录，别脏了仓库。

**implementer 一律用后台跑。** 实测回流耗时 350~580 秒，Bash 工具前台上限是 600 秒——
三次派活里有一次会撞上限被踢到后台，然后你还要额外花几轮去捞输出。
一开始就 `run_in_background: true`，等通知。verifier 通常一分钟内回来，前台跑就行。

## 任务书：复制模板填空，不要即兴写

三份模板在 `~/.claude/skills/dev-cycle/templates/`：

| 派谁 | 模板 |
|---|---|
| `implementer` | `task-implementer.md` |
| `verifier` | `task-verifier.md` |
| `explore` | `task-explore.md` |

复制到临时目录 → 逐个 `<>` 填空 → 删掉顶部注释块 → 派出去。
**小节顺序和标题不许改**，执行端按这个形状读。

模板的五段骨架就是执行端需要的全部：**改哪些文件 → 每处改什么 → 完成标准 →
验收命令 → 红线**。填空比从空白页写快，也比即兴写稳——即兴写每次都要重新想一遍
「该交代什么」，那正是最贵的那种轮次。

### 执行后端看不见你的对话

它是另一个进程、另一个模型，**只能看到你写进任务文件的东西**。所以：

- **第 2 步得出的约束和红线必须逐条抄进去**——它们不在任何文档里，不抄它就看不到。
  不要写"按之前说的办"。
- **已有文档里的背景一律指路，不抄正文**——执行后端读得到仓库，
  写"先读 docs/xxx.md 的 YY 节"远比把那一节抄进任务书便宜。

## 成本纪律

### 省的是你这边，不是 Reasonix 那边

Reasonix 跑 deepseek 档，一次调用的 ~24k 系统提示合几分钱。
**贵的是你的上下文**——子代理返回的每个字都进你这里，还会在后续每轮重发。所以：

- **按独立性拆活，不要为了省调用次数硬合并。** 合并只省 Reasonix 那几分钱，
  代价是几件事的证据混在一起、返回更长、其中一件出问题时打回的任务文件还得
  把三件事的上下文重写一遍。**但互相耦合的必须合在一起派**——B 依赖 A 定下来的
  接口形状时拆开会拿到两套不一致的实现，那才是真烧钱。
- **模型档位不用手调，默认就够。** 第一轮所有角色都走后端默认档。
  **只有一种情况才升档：implementer 被你打回过一轮且原因是它写崩了**（不是任务写虚了、
  也不是约束没抄全）——这时下一轮加 `--model pro` 重派。
  **打回原因是你自己没写清楚的，升档没用，回去改任务文件。**
- **implementer 用 `--max-chars 6000`、explore 用 `--max-chars 3000`**，
  被裁的部分落到临时文件，`[rx]` 那行会给路径，需要细看时再去读。
- **verifier 不要设 `--max-chars`。** 它的返回本来就是压缩过的（一张表加 FAIL 原文），
  而那些原文正是你验收要吃的证据，裁掉就等于白跑。

### 最贵的是「停下来想」的轮次，不是写出来的字

2026-08-11 三个派活会话的实测账本：**47% 的轮次不带任何工具调用，它们吃掉 54% 的输出
token**。但这些轮次里**只有 12% 是写给用户看的字，另外 88% 是推理**——三个会话加起来
面向用户的正文只有 3,597 字。**所以「汇报写短」几乎省不出东西，省下来的是审议轮本身。**
四条：

- **任务书用模板填空，别从空白页写。** 见上一节。即兴写任务书是最典型的
  「纯审议 + 长输出」组合。
- **重验收动作按批做。** 同型工作单元（一批页面、一批窗口）连续派活时，截图渲染、
  全量测试这类贵动作每 2~3 个单元集中做一次；迭代中只跑最小档位（单档截图、定向测试），
  全档位留到批次末和里程碑。逐单元全流程验收是把最贵的动作乘了单元数。
- **任务跟踪工具只在里程碑用。** TaskCreate/TaskUpdate 实测占了派活会话 8.8% 的输出
  token（23 次调用 27,691 token），换来的只是一份待办清单。检查点粒度就够。
- **到里程碑就收尾，别让会话滚厚。** 实测三个会话平均每轮重读 99k 上下文。
  长流水线在里程碑处写完汇报就结束会话，让用户拿检查点结论开新会话续下一段——
  新会话重读的是几百行结论，不是几万行过程。

## 0. 铺路（每个项目只做一次）

```bash
python ~/.claude/scripts/rx.py doctor
```

绿了就往下走。有红的、或者这个项目没铺过 → 读 `references/setup.md` 按它办。
**任何情况下你都不碰用户的密钥，也不改 `~/.codex/config.toml`。**

## 1. 摸底

读项目的指令文件（`AGENTS.md` / `CLAUDE.md` / `CONTRIBUTING.md`，取第一个存在的）、
它点名要读的其他文档、`git status --short --branch` 和最近几条提交、任务涉及的现有代码。

**指令文件和 git 状态必须你自己读**，那是宪法和现场，不外派。

项目自带的专用技能能覆盖这个任务，**先用那个技能**，它比临场推准。

### 大海捞针才派 explore

只有"这事牵扯到哪些地方我完全没数"时才值得派。已经知道改动就在一两个文件里的小活，
你直接 Glob/Grep 比派一轮快得多。用 `task-explore.md` 模板。

**三条不能破的边界**：

1. **explore 的返回是线索，不是证据。** 拿到清单后**你自己去读那些文件的原文**。
   第 2 步的影响面和红线检查只能吃你亲眼读过的代码，不能吃它的摘要——
   它是便宜档模型，不会漏掉你点名要找的东西，但会漏掉**你不知道该找的东西**：
   那个没人预料到的耦合、那句 `// 别动这里，见 BUG-1234` 的注释。
2. **它说"没有别的相关文件"不算数。** 那可能只是它没找到。按清单读完之后，
   如果代码里引用了清单之外的东西，自己补搜。
3. **它给的任何方案倾向一律忽略。** 设计审查是第 2 步的事，不接受外部输入。

## 2. 设计审查（你亲自做）

不派子代理，不外包，就是你自己想。产出六项，写进回复里：

1. **真正要解决的问题**——用户说的和实际要改的往往不是一回事。
2. **影响面**——动到哪些模块、哪些边界、有没有协议或接口变更。
3. **红线检查**——把项目指令文件里的硬约束逐条过一遍。没有指令文件时至少过这几条：
   凭据会不会进 Git / 日志？有没有对外暴露端口或放宽认证？有没有依赖某个具体实现
   而不是抽象边界？用户可见文案有没有内部黑话？涉不涉及不可恢复的删除？
4. **方案 + 至少一个被否掉的替代方案**，写清为什么否。
5. **验证矩阵**——改完要跑哪些门禁才算数。
6. **任务拆分**——拆成能独立交给 `implementer` 的条目。**按独立性拆，不按大小拆**：
   互不依赖的分开派，B 依赖 A 定下来的接口形状的必须合并派。

**红线冲突时停下来问用户。** 这是整条流程里唯一允许中断的地方。方案取舍你自己定。

## 3. 实现（派 implementer）

用 `task-implementer.md` 模板填空，后台派出去：

```bash
python ~/.claude/scripts/rx.py sub implementer --max-chars 6000 - < 任务文件
```

模型走后端默认档，别自己加 `--model`。只有它上一轮**写崩了**被你打回，
这一轮才升档重派（reasonix 侧 `--model pro`，codex 侧 `--model sol`）。

## 4. 验证（派 verifier）

用 `task-verifier.md` 模板填空。把改动范围告诉它，让它按范围决定跑哪些门禁。

```bash
python ~/.claude/scripts/rx.py sub verifier - < 任务文件      # 注意：不加 --max-chars
```

`implementer` 自己跑过的 lint 不算验证，那只是自查。完整验证必须由 `verifier` 独立跑。

真正保证"它改不了源码"的是 `rx.py` 的工作区哨兵：它在 verifier 跑之前和跑完各取一次
`git diff` 指纹。**`[rx]` 行里出现 `tree=modified` → 这一轮验证作废，不许拿它的表当证据。**
让它重跑一次，或者查清是哪条命令写了文件。看到 `tree=clean` 才算数。

## 5. 验收（你）

现在是另一个模型在替你干活，验收要比自己动手时更硬。逐条过：

- **证据是真的吗？** verifier 那张表的「关键输出行」栏有没有命令自己打出来的字？
  只有命令没有输出、或者写着"已执行"的，当没跑。
- **无条件自己复跑一条。** 挑一条最能说明本次改动的快门禁（类型检查，或覆盖这次改动的
  那个测试），你自己用 Bash 跑一遍。**不要改成"证据可疑时才跑"**——会编证据的模型
  编出来的东西看着就是不可疑的，那正是这条要防的失败。为省上下文按退出码分流：

  ```bash
  命令 2>&1 | tail -30    # 绿的时候只留尾部；非 0 退出就重跑一次拿完整输出
  ```

- **验证矩阵覆盖了吗？** 第 2 步列的项是不是都有结果？漏了补跑。
- **UNAVAILABLE 写清原因了吗？** 没写清就是 FAIL。
- **改动范围有没有超纲？** `git diff --stat` 扫一眼有没有顺手改的无关模块。
- **`[rx]` 行有没有 `tree=modified`？** 有就是 verifier 自己动了源码，这轮作废，重跑。
- **implementer 改了既有测试吗？** 它的回流第 4 节。改断言等于动验收标准本身，
  逐条看过才算数——偷偷把红的断言改绿，是这条流程唯一防不住的失败。
- **任务书和现场对不上吗？** 它的回流第 6 节。换了解释器、现装了依赖、补了配置文件，
  都会让验证结论打折扣。
- **临时产物清了吗？** 它的回流第 7 节。探针脚本、调试脚本该删的删掉再提交。

有 FAIL 或缺口 → 写一份**只讲具体缺口**的新任务文件打回给 `implementer`，再验一轮。
**最多来回 3 轮**；3 轮不绿就停下来，把卡住的点原原本本告诉用户，不要继续烧钱。

全绿后再提交，提交信息按项目习惯。当前在主分支就先开分支。

## 6. 汇报

只写四块，大白话，不贴堆栈不贴命令：

1. **做了什么**——从用户的角度说，不是从代码角度。
2. **验证结果**——哪些跑过了、哪些因为环境跑不了。
3. **怎么用 / 怎么看效果**——具体到点哪里、开哪个东西。
4. **需要他知道的**——遗留问题、新发现的 Bug。没有就不写。

最后固定加一行**派活账**，格式写死：

```
派活账：派活 N 次（implementer A / verifier B / explore C），一次过 M 次，打回 K 次（写崩 X / 任务没写清 Y / 环境不符 Z）。
```

**打回原因必须分类**，三类的处置完全不同：写崩了 → 下一轮升档；任务没写清 → 回去改
任务文件，升档没用；环境不符 → 补进任务书的「环境」节。
一次都没打回就写 `一次过 N 次，打回 0 次`。**这一行不许省**——
它是唯一能让「执行端到底行不行」积累出数字的地方，省一次就断一次。

**花费**：reasonix 后端不要报（拿不到 usage 信封，编一个比不报更糟）；
codex 后端照抄 `[rx]` 行里的 `in= / cached= / out=`，**不要自己折算成钱**。

项目有术语表就按术语表说话，别把内部黑话漏给用户。
